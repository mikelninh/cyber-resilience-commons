# Product Spec — Public v1

## User journey
1. Choose an organization template.
2. Optionally customize name, identity count, critical service, and sensitive data.
3. Choose one synthetic incident scenario.
4. Mark current defensive boundaries as enabled/disabled.
5. Inspect the deterministic incident path and modeled blast radius.
6. Enable a boundary and rerun the same scenario.
7. Review the top three highest-leverage missing boundaries.
8. See a concrete suggestion for how each control could be validated in an owned/authorized environment.
9. Review recovery drill assumptions.
10. Download or print a resilience brief.

## Included templates
- City / public administration
- Hospital / care provider
- School / education network
- NGO / nonprofit
- Small business

## Included scenarios
- Stolen credentials
- Ransomware on one device
- Compromised vendor
- Bulk data exfiltration
- Stolen SaaS / OAuth token

## Required truth boundary
The product must never present synthetic planning output as a pentest, vulnerability assessment, certification, prediction of compromise, or proof of real-world security.
