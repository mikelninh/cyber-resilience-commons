# Design principles

1. **Assume compromise.** Resilience begins after prevention fails.
2. **Show the path.** A user should see why a result changes, not trust a magic score.
3. **Same incident, changed boundary.** Causal comparison is more useful than generic advice.
4. **Action before jargon.** Explain what to do, why it matters, and how to prove it.
5. **Recovery is security.** Restoration, revocation, communication, and continuity belong in the same model.
6. **Unknown is visible.** Never silently convert missing information into “safe.”
7. **Synthetic is labeled.** Model values are assumptions, not empirical predictions.
8. **Real validation is authorized.** Proof belongs in owned or explicitly authorized environments.
9. **Private by default.** Keep organization planning data local unless the user deliberately chooses otherwise in a future mode.
10. **Commons over lock-in.** Make useful patterns reusable by organizations with small budgets and small security teams.
